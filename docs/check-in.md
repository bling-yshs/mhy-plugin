# 游戏签到

当前实现国服原神、星铁和绝区零的每日游戏签到。国际服会记录失败并提示当前范围。

## 命令

- `#签到`、`#原神签到`：手动签到原神。
- `#星铁签到`、`#绝区零签到`：手动签到对应游戏。
- `#开启原神自动签到`、`#开启星铁自动签到`、`#开启绝区零自动签到`。
- 将“开启”替换为“关闭”即可关闭。
- `#自动签到状态`：每个关联账号用两行展示账号 ID 和三个游戏的开关。

命令仅操作发送者本人绑定的账号。开启或关闭作用于当时绑定且拥有该游戏角色的全部米游社账号；后来新绑定的账号需再次开启。账号下后续同步的角色随账号设置生效。共享账号的开关由关联用户共同管理。最后一个用户解绑账号时删除自动签到配置。

## 执行规则

自动签到使用云崽调度器的 `0 2 0 * * *`，每天北京时间 00:02 直接触发一次。机器人进程采用北京时间，没有启动补跑。手动签到覆盖发送者所有已绑定账号的对应游戏角色。

自动签到在请求前写入当天记录，任何已有记录都会阻止当天自动重复执行，包括失败和进程中断。仅用户手动发送签到命令可以再次尝试并更新当天记录。没有自动重试、租约、超时接管。进程内同一角色并发请求直接返回正在执行。

同一米游社账号、同一游戏最近三个有记录的日期连续，且这三天的签到记录全部失败时，自动关闭该游戏的自动签到。任一天出现成功、已签到或执行中记录都会中断连续失败判定。关闭后保持静默，只记录日志；手动签到仍可使用。用户重新开启后，从此次开启时间重新统计，原有签到记录保留。

## SQLite

Sequelize 在启动时创建当前模型的缺失表，无历史数据导入。

- `AutoSignSettings`：`ltuid`、`game` 联合主键，`enabled`、`created_at`、`updated_at`。
- `SignRecords`：`game`、`region`、`uid`、`sign_date` 联合主键，`ltuid`、`status`、`result`、`created_at`、`updated_at`。
- `result` 是 TEXT JSON，保存 `info`、`sign`、`home` 原始响应及遇到的异常，不脱敏；手动再次执行替换当天结果。
- 成功但奖励接口失败时保留签到成功，单独保存奖励请求错误。
- `total_sign_day` 按本月累计签到天数展示。

## 协议与验证

三游戏 act_id、`event/luna/info|home|sign`、DS1 和 signgame 请求头参考本地 GT-Manual 的 `model/mysApi.js`。本地 SDK `luna.tsp` 的路径带额外游戏段，与现有插件不一致，本次沿用插件实际使用路径和角色参数。

请求经 mhy-plugin 的统一账号、设备及 lib/fetch 链路。签到操作绕过旧查询缓存。失败原因原样回复，完整结果在 SQLite 内保留，验证码不自动处理。

静态检查使用 `pnpm check`。按用户要求不执行测试，不调用真实签到接口；国服三个游戏的实际签到、奖励、验证码分支待用户实测。上线前运行 `pnpm build` 并重启机器人，关闭其他插件重叠签到命令。
