# 历史迁移与运行时边界

## 适用范围

历史 SQLite 升级、旧 YAML／Redis 导入、回退资料及历史契约测试统一存放于根目录 `migration/`。

## 入口

- `node migration/upgrade-database.mjs --database <SQLite路径>`：手动补充历史表字段。
- `node migration/import-legacy.mjs --database <SQLite路径> [--apply]`：预览或导入历史数据。
- `src/db/index.ts`：定义最新模型并创建缺失的表。

## 契约

运行时依赖链仅使用最新结构，保持 `migration/` 为独立入口。数据库模块加载时禁止执行历史字段探测、补列、备份或旧来源导入。当前其他插件调用的模型和原始响应契约继续有效。

## 校验与错误

| 情况 | 行为 |
| --- | --- |
| 全新库 | 主插件按最新模型创建表 |
| 历史表缺少凭据列 | 运行时保持表原样，用户手动运行升级命令 |
| 迁移路径不存在 | 工具失败，保留原路径状态 |
| 迁移目标缺少 `MysUsers` | 报告目标数据库错误 |
| 已完成升级 | 再次运行返回空新增列列表和空备份路径 |
| 旧库直接正式导入 | 提示先执行升级命令 |

## 场景

新安装直接启动；旧安装先停止机器人、手动升级、按需导入再启动。旧库直接启动时不会发生隐式升级，使用新字段的查询可能失败。

## 回归验证

`tests/` 使用最新结构准备业务数据。`migration/tests/` 覆盖旧库保持原样、显式升级备份、重复执行、来源保留和历史响应契约。断言主插件启动后旧表仍缺少新增列且没有产生备份。

## 示例

启动路径包含 `await migrateDatabase()` 会产生隐式迁移，属于边界违规。约定的启动路径使用当前模型 `sync()` 创建缺失表，历史补列在 `migration/upgrade-database.mjs` 中显式执行。
